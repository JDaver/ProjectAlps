# Graph Generation

The `GraphInstance` is responsible for generating the connectivity graph between the `RegionNode` instances previously generated by `RegionNodesInstance`.

The graph generation process does **not create new regions**. All nodes already exist before this phase begins. The responsibility of this phase is to determine how those nodes are connected while respecting the connectivity rules defined by each `SubRegion`.

The generation process is divided into three phases:

1. Initial graph construction
2. Graph completion
3. Optional loop generation

---

## 1. Input

`GraphInstance` receives a `RegionNodesInstance` and a random seed:

```csharp
public GraphInstance(
    RegionNodesInstance nodesInstance,
    int seed
)
```

The `RegionNodesInstance` contains the complete collection of generated `RegionNode` objects.

Each node contains information such as:

* `Id`
* `RegionTypeId`
* `Name`
* `Elevation`
* `Neighbours`

The `NodeLoader` provides the rules associated with each `RegionTypeId`.

The `ArchetypeInstance` provides the global connectivity parameters:

* `NumberRegions`
* `MinLinksPerNode`
* `MaxLinksPerNode`
* `BranchingPreference`
* `LoopsProbability`
* `AllowLoops`

---

# 2. Available Nodes

At construction time, all generated nodes are grouped by their `RegionTypeId`.

```csharp
availableNodes = nodesInstance.RegionsCollection
    .Values
    .GroupBy(n => n.RegionTypeId)
    .Select(g => new AvailableNode(g.ToList()))
    .ToList();
```

This allows the algorithm to keep track of how many nodes of each region type are still available.

For example:

```text
Forest1
    ├── Node 1
    └── Node 7

AlpineTundra
    ├── Node 3
    └── Node 5

AlpinePass
    ├── Node 0
    └── Node 2
```

`AvailableNode` acts as a container for nodes belonging to the same region type.

---

# 3. Initial Node

The graph starts from the currently available node with the lowest elevation.

```csharp
RegionNode startNode = ExtractMinorAltitudeNode();
```

The selected node is:

1. removed from the available nodes;
2. added to the graph;
3. inserted into the BFS queue.

```text
Lowest elevation node
        │
        ▼
     Graph
        │
        ▼
     BFS Queue
```

This provides a deterministic starting point for the graph construction while maintaining the general altitude progression of the generated world.

---

# 4. Initial Graph Construction

The first construction phase uses a breadth-first traversal.

```csharp
Queue<RegionNode> queue
```

For every node extracted from the queue, the algorithm determines how many connections should be attempted.

```csharp
int numberOfLinks =
    CalculateNumberOfLinks(
        minLinks,
        maxLinks,
        branchingPreference
    );
```

The number of attempted connections is determined probabilistically between `MinLinksPerNode` and `MaxLinksPerNode`.

`BranchingPreference` controls the probability of adding additional links.

This parameter therefore influences the branching factor of the generated graph.

---

# 5. Candidate Selection

For every connection that needs to be generated, the algorithm searches for the best compatible available node.

```csharp
PickHighestScoreNode(
    current,
    nodeLoader
);
```

Candidate selection consists of two steps:

1. Compatibility filtering
2. Score evaluation

Only nodes that pass the compatibility test are considered.

---

# 6. Region Compatibility

A connection between two regions is allowed only when both region types explicitly allow each other.

```csharp
private bool IsCompatible(
    RegionNode current,
    RegionNode candidate,
    NodeLoader nodeLoader)
```

The algorithm retrieves the rules of both region types:

```csharp
SubRegionRules currentRules =
    nodeLoader.RegionTypes[current.RegionTypeId];

SubRegionRules candidateRules =
    nodeLoader.RegionTypes[candidate.RegionTypeId];
```

A connection is valid only when:

```text
current → candidate
```

is allowed **and**

```text
candidate → current
```

is allowed.

In other words, connectivity is treated as a bidirectional compatibility constraint.

```csharp
return currentAllowsCandidate &&
       candidateAllowsCurrent;
```

Therefore, if:

```text
A allows B
B does not allow A
```

the connection is rejected.

This prevents the graph generation algorithm from creating connections that are not defined by the `SubRegion` rules.

---

# 7. Candidate Score

After incompatible candidates have been removed, the remaining candidates are ranked using:

```csharp
CalculateScore()
```

The score combines three factors:

```text
Score =
    Distance Score
    × Availability
    × Cluster Penalty
```

The current implementation is:

```csharp
return distanceScore
    * availability
    * cluster;
```

---

## 7.1 Elevation Distance

The first factor evaluates the elevation difference between the current node and the candidate.

```csharp
float distance = Math.Abs(
    current.Elevation - node.Elevation
);
```

The distance is normalized using the maximum elevation range:

```csharp
float distanceScore =
    1f - Math.Clamp(
        distance / maxElevationDistance,
        0f,
        1f
    );
```

A candidate with an elevation close to the current node receives a higher score.

Therefore:

```text
small elevation difference
        ↓
higher distance score
```

while:

```text
large elevation difference
        ↓
lower distance score
```

---

# 7.2. Availability

The second factor takes into account how many nodes of the candidate's region type are still available.

```csharp
float availability =
    1f / candidate.Occurrences;
```

A region type with fewer available instances receives a higher availability factor.

This encourages the algorithm to avoid concentrating the graph exclusively around region types with many available instances.

---

# 7.3. Cluster Penalty

The third factor reduces the score of candidates whose region type is already concentrated around the current node.

```csharp
CalculateClusterPenalty(
    current,
    candidate
);
```

The algorithm performs a BFS around the current node up to:

```csharp
private const int ClusterDepth = 2;
```

The concentration of the candidate region type is calculated using the inverse of its distance from the current node.

```csharp
concentration += 1f / neighbourDepth;
```

Therefore:

```text
depth 1 → 1.0
depth 2 → 0.5
```

A region of the same type directly connected to the current node therefore contributes more to the concentration than a region two steps away.

The final penalty is:

```csharp
return 1f / (1f + concentration);
```

As the local concentration increases, the penalty decreases.

This discourages excessive clustering of the same region type.

---

# 8. Adding a Node

Once the highest-scoring compatible candidate has been found, the node is consumed from the available collection.

```csharp
RegionNode node = candidate.Consume();
```

It is then added to the graph:

```csharp
Graph.AddNode(node);
Graph.AddEdge(current, node);
```

Finally, it is added to the BFS queue so that it can generate further connections.

```csharp
queue.Enqueue(node);
```

The process continues until either:

* the requested number of regions has been reached;
* the BFS queue becomes empty;
* no compatible candidate is available for the current node.

---

# 9. Graph Completion

The initial BFS construction is intentionally greedy.

Because compatibility rules are strict, it is possible for the BFS to reach a node for which no compatible unused node exists, even though other nodes could still be connected elsewhere in the graph.

For this reason, a second phase is executed:

```csharp
CompleteGraph(nodeLoader);
```

The purpose of this phase is to connect remaining nodes without changing the already generated graph.

---

## 9.1 Completion Strategy

For every remaining `AvailableNode`, the algorithm checks every existing node in the graph.

```csharp
foreach(AvailableNode candidate in availableNodes)
{
    RegionNode node = candidate.Peek();

    foreach(RegionNode existing in Graph.Nodes.Values)
    {
        ...
    }
}
```

A candidate is considered only if it is compatible with the existing node.

```csharp
if(!IsCompatible(
    existing,
    node,
    nodeLoader))
{
    continue;
}
```

The same scoring system used during the initial construction is then applied.

Therefore, graph completion still considers:

* elevation distance;
* availability;
* local clustering.

The best `(candidate, existing node)` pair is selected globally.

The remaining node is then added:

```csharp
Graph.AddNode(newNode);
Graph.AddEdge(bestParent, newNode);
```

This process continues until:

* all nodes have been connected;
* or no compatible connection exists anywhere in the graph.

---

# 9.2 Why Graph Completion Is Separate

The two construction phases have different purposes.

### Initial construction

The initial phase follows the graph outward using BFS:

```text
Current node
     ↓
Compatible candidates
     ↓
Best candidate
     ↓
New node
     ↓
Queue
     ↓
Next node
```

This produces the main structure of the world.

### Completion

The completion phase searches globally:

```text
Remaining nodes
       ↓
All existing graph nodes
       ↓
Compatible pairs
       ↓
Best global score
       ↓
Add connection
```

This prevents the generation process from stopping prematurely simply because the current BFS branch has no valid continuation.

---

# 10. Loop Generation

After the graph has been completed, optional loops can be generated.

Loops are enabled by:

```csharp
archetypeInstance.Connettivity.AllowLoops
```

and their probability is controlled by:

```csharp
LoopsProbability
```

When enabled:

```csharp
GenerateLoops(
    startNode,
    nodeLoader,
    loopsProbability
);
```

---

# 10.1 Loop Detection

Loop generation performs another BFS traversal of the generated graph.

For every node, the algorithm obtains its current neighbours:

```csharp
List<RegionNode> neighbours =
    current.Neighbours.ToList();
```

It then examines every pair of neighbours.

For example, if:

```text
       A
      / \
     B   C
```

the algorithm tests whether:

```text
B ── C
```

should be added.

This is how potential shortcuts between existing branches are discovered.

---

# 10.2 Loop Validation

Every potential loop is passed to:

```csharp
ValidateLoop()
```

A loop is rejected immediately if:

```csharp
a.Neighbours.Contains(b)
```

because the connection already exists.

A random probability check is then performed:

```csharp
rng.NextSingle() > loopsProbability
```

Only candidates that pass this probability check continue to compatibility validation.

Finally, the same bidirectional `LinkRules.Neighbours` constraint used during normal graph construction is applied.

```csharp
bool compatible =
    rulesA.LinkRules.Neighbours.Contains(b.RegionTypeId)
    &&
    rulesB.LinkRules.Neighbours.Contains(a.RegionTypeId);
```

If the connection is valid:

```csharp
Graph.AddEdge(a, b);
```

A new edge is therefore never created solely because two nodes are close in the graph. The connection must also be explicitly allowed by both region types.

---

# 11. Complete Generation Pipeline

The complete algorithm can be summarized as:

```text
RegionNodesInstance
        │
        │
        ▼
Group nodes by RegionTypeId
        │
        ▼
Select lowest-elevation start node
        │
        ▼
Initial BFS construction
        │
        ├── Calculate number of links
        │
        ├── Filter incompatible candidates
        │
        ├── Calculate candidate score
        │
        └── Add best candidate
        │
        ▼
     CompleteGraph
        │
        ├── Check remaining nodes
        ├── Check all existing graph nodes
        ├── Filter incompatible pairs
        └── Add globally best connection
        │
        ▼
   AllowLoops ?
      /      \
    No        Yes
    │          │
    │          ▼
    │     GenerateLoops
    │          │
    │          ├── BFS graph
    │          ├── Find neighbour pairs
    │          ├── Probability check
    │          └── Compatibility check
    │
    └──────────┬──────────
               ▼
          Final Graph
```

---

# 12. Determinism

The graph generation uses a `System.Random` initialized with the supplied seed:

```csharp
rng = new Random(seed);
```

The seed controls all random decisions performed by `GraphInstance`, including:

* branching decisions;
* loop probability checks.

Given the same generated `RegionNodesInstance`, configuration and seed, the graph generation process is deterministic.

---

# 13. Design Principles

The current algorithm follows several important principles.

### Region generation and graph generation are separate

`RegionNodesInstance` determines:

> **What regions exist?**

`GraphInstance` determines:

> **How are those regions connected?**

This separation prevents graph generation from creating or replacing region types.

### Compatibility is a hard constraint

`LinkRules.Neighbours` is not used as a preference.

If two region types are incompatible, the connection is rejected.

### Scoring is a soft preference

Elevation, availability and clustering do not define whether a connection is possible.

They determine which valid connection is preferred.

### Completion is separate from construction

The initial BFS provides the main graph structure, while `CompleteGraph()` handles nodes that could not be reached by the greedy traversal.

### Loops are optional

The base graph can be generated without loops.

When enabled, loops are added afterward as additional edges between already connected parts of the graph.
